# 🛒 متجر مريم — نموذج أولي معياري لمتجر أدوات منزلية

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https://github.com/l08072978-cmyk/test/tree/claude/home-tools-store-prototype-f6quil)

نموذج أولي (prototype) لمتجر إلكتروني لبيع الأدوات المنزلية، مبني بمعمارية
**معيارية (Modular)** قابلة للتوسعة. كل ميزة مكتفية بذاتها داخل مجلد مستقل،
ويتم اكتشافها وتحميلها تلقائيًا — فإضافة ميزة جديدة لا تتطلب تعديل النواة.

> مبني بـ **Node.js خالص** (بدون أي اعتماديات خارجية) ليعمل مباشرة.

---

## التشغيل

```bash
npm start        # تشغيل الخادم
npm run dev      # تشغيل مع إعادة التحميل التلقائي
npm test         # تشغيل الاختبارات
```

ثم افتح المتصفح على: <http://localhost:3000>

---

## البنية المعمارية

```
src/
├── server.js              # نقطة الدخول
├── app.js                 # تجميع التطبيق + التوجيه + الملفات الثابتة
├── config/                # الإعدادات المركزية
├── core/                  # النواة (لا تحتوي منطق أعمال)
│   ├── database.js        #   طبقة تخزين مجرّدة (حاليًا في الذاكرة)
│   ├── router.js          #   موجّه HTTP بسيط
│   ├── http.js            #   أدوات الطلب/الاستجابة
│   └── moduleLoader.js    #   مُحمّل الوحدات التلقائي ← جوهر المعيارية
└── modules/               # الوحدات (الميزات)
    ├── categories/        #   التصنيفات
    ├── products/          #   المنتجات
    └── cart/              #   سلة التسوق
public/                    # واجهة المتجر (HTML/CSS/JS)
test/                      # الاختبارات
```

كل وحدة تُصدّر:
- `name` — اسم الوحدة.
- `register(router)` — تسجيل مساراتها.
- `seed()` *(اختياري)* — تعبئة بيانات أولية.
- `service` — منطق الأعمال (يُعاد استخدامه بين الوحدات والاختبارات).

## واجهة الـ API

| الوسيلة | المسار | الوصف |
|--------|--------|-------|
| GET | `/api/categories` | قائمة التصنيفات |
| POST | `/api/categories` | إضافة تصنيف |
| GET | `/api/products?categoryId=&search=` | قائمة المنتجات (مع تصفية) |
| GET | `/api/products/:id` | منتج واحد |
| POST | `/api/products` | إضافة منتج |
| PATCH | `/api/products/:id` | تعديل منتج |
| DELETE | `/api/products/:id` | حذف منتج |
| GET | `/api/cart/:sessionId` | عرض السلة |
| POST | `/api/cart/:sessionId/items` | إضافة عنصر `{ productId, quantity }` |
| DELETE | `/api/cart/:sessionId/items/:productId` | حذف عنصر |
| DELETE | `/api/cart/:sessionId` | تفريغ السلة |

## كيف تضيف ميزة جديدة (التوسعة)

أنشئ مجلدًا في `src/modules/` يحوي `index.js` يُصدّر `register` و(اختياريًا) `seed`.
سيكتشفه المُحمّل تلقائيًا. أمثلة لميزات مستقبلية:

- **`orders/`** — الطلبات وإتمام الشراء (Checkout).
- **`users/` و `auth/`** — الحسابات وتسجيل الدخول.
- **`payments/`** — بوابات الدفع.
- **`reviews/`** — تقييمات المنتجات.
- **`admin/`** — لوحة تحكم لإدارة المتجر.

## النشر على Vercel

المشروع مُهيّأ للعمل على Vercel كـ serverless:
- الملفات الثابتة في `public/` تُخدَم من شبكة Vercel.
- كل مسارات `/api/*` تمرّ عبر الدالة `api/[...path].js`.
- الإعداد في `vercel.json`.

**للنشر عبر لوحة التحكم (موصى به):**
1. افتح <https://vercel.com/new>.
2. استورد مستودع GitHub: `l08072978-cmyk/test`، واختر الفرع
   `claude/home-tools-store-prototype-f6quil`.
3. اترك الإعدادات الافتراضية (Framework: Other) واضغط **Deploy**.
4. سيُولّد Vercel رابطًا عامًا للاختبار تلقائيًا.

> ملاحظة: التخزين حاليًا في الذاكرة، لذا تُعاد البيانات إلى حالتها الأولية
> مع كل بدء بارد للدالة — مناسب للاختبار، ويُستبدل بقاعدة بيانات لاحقًا.

## خطوات التطوير المقترحة لاحقًا

1. استبدال طبقة التخزين في الذاكرة بقاعدة بيانات حقيقية (PostgreSQL/MongoDB)
   عبر تنفيذ نفس واجهة `core/database.js`.
2. إضافة المصادقة والصلاحيات (JWT).
3. إضافة وحدة الطلبات والدفع.
4. التحقق من المدخلات بمكتبة مخصصة، ومعالجة موحّدة للأخطاء.
5. إضافة لوحة تحكم للمشرف، ودعم رفع صور المنتجات.
